# Offline installation

Hospital and laboratory networks are often isolated from the internet. OXIM needs no network access to install or run, and the offline bundle contains everything for one platform in a single archive.

| Bundle | Platform |
|---|---|
| `oxim-<version>-x86_64-unknown-linux-gnu.tar.gz` | Linux x86_64 with systemd, glibc 2.28 or later |
| `oxim-<version>-aarch64-unknown-linux-gnu.tar.gz` | Linux ARM64 with systemd, glibc 2.28 or later |
| `oxim-<version>-x86_64-pc-windows-msvc.zip` | Windows x64 |
| `oxim-<version>-aarch64-pc-windows-msvc.zip` | Windows ARM64 |
| `oxim-<version>-x86_64-apple-darwin.tar.gz`, `...-aarch64-apple-darwin.tar.gz` | macOS; the binary only, run it under launchd yourself |

Each bundle holds the program, the configuration template, example channels and tables, these guides, the licenses, install and uninstall scripts, and `SHA256SUMS` of its content. The deb, rpm and MSI packages also install without network access; the bundle is for machines where package managers are not used or the package format does not fit.

## Transfer and verify

On a connected machine, download the bundle, `SHA256SUMS` and `SHA256SUMS.sigstore.json` from the release and verify them as described in [the overview](README.md#verifying-a-download). Copy the bundle to the target machine with the approved transfer medium and check it again there:

```sh
sha256sum --check --ignore-missing SHA256SUMS
```

```powershell
(Get-FileHash oxim-<version>-x86_64-pc-windows-msvc.zip -Algorithm SHA256).Hash
```

The install scripts verify every file of the bundle against its `SHA256SUMS` before installing.

## Linux

```sh
tar -xzf oxim-<version>-x86_64-unknown-linux-gnu.tar.gz
cd oxim-<version>-x86_64-unknown-linux-gnu
sudo ./install.sh            # add --start to start the service right away
```

`install.sh` creates the `oxim` account and the directories of the [Linux layout](linux.md), installs `/usr/local/bin/oxim`, keeps an existing `/etc/oxim/oxim.yaml`, writes the systemd unit generated by the binary (`oxim service unit`) with the packaging drop-in, and enables the service. Running it again upgrades an installation and restarts a running service. Do not combine it with the deb or rpm package on the same machine.

```sh
sudo ./uninstall.sh          # keeps /etc/oxim, /var/lib/oxim and /var/log/oxim
sudo ./uninstall.sh --purge  # deletes them too, including stored messages
```

## Windows

Extract the zip, then from an elevated PowerShell in the extracted folder:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1          # add -Start to start the service
```

`install.ps1` installs to `%ProgramFiles%\OXIM`, prepares `%ProgramData%\OXIM` (readable only by SYSTEM and Administrators), keeps an existing `oxim.yaml`, adds OXIM to the system `PATH` and registers the service with `oxim service install`. Running it again upgrades an installation. Do not combine it with the MSI on the same machine.

```powershell
powershell -ExecutionPolicy Bypass -File "$env:ProgramFiles\OXIM\uninstall.ps1"          # keeps %ProgramData%\OXIM
powershell -ExecutionPolicy Bypass -File "$env:ProgramFiles\OXIM\uninstall.ps1" -Purge   # deletes it too
```

## Container images

To move the image into an isolated registry:

```sh
docker pull ghcr.io/oxim-health/oxim:<version>
docker save ghcr.io/oxim-health/oxim:<version> -o oxim-<version>.tar
# transfer the file, then on the isolated side:
docker load -i oxim-<version>.tar
```

## Building a bundle

```sh
cargo build --release --locked -p oxim --target x86_64-unknown-linux-gnu
deploy/offline/build-bundle.sh --version 1.0.0 --target x86_64-unknown-linux-gnu \
  --binary target/x86_64-unknown-linux-gnu/release/oxim
```

```powershell
.\deploy\offline\build-bundle.ps1 -Version 1.0.0 -Target x86_64-pc-windows-msvc `
  -Binary target\x86_64-pc-windows-msvc\release\oxim.exe
```
